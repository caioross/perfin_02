Login com e-mail/senha e Google

Portal Perfin e site institucional · plano de execução e instruções · outubro de 2026

Objetivo. No site, o botão Entrar / Cadastrar fica no canto superior direito. Ele abre a tela do Portal onde a pessoa entra ou cria conta com e-mail e senha ou com Google. Junto vêm os ajustes no banco (Supabase) e a automação de testes das PRs no GitHub (CI).

Decisões tomadas

TemaDecisão
Cadastro por e-mailAcesso imediato depois de confirmar o e-mail (papel usuario).
Onde fica o formulárioNo Portal. Site e Portal estão em endereços diferentes na Vercel e não compartilham login, então há um único lugar de login.
Agenda, Relatório e Gmail para quem entrou por e-mailAviso “Disponível para quem entra com Google”. Por segurança, esses recursos ficam só com contas criadas pelo Google.

A URL que você procura (Google Cloud)

URI de redirecionamento autorizado:
https://tphqjblaspvyflzjinkq.supabase.co/auth/v1/callback
É a mesma para o site e para o app: o Google sempre devolve para o Supabase, e o Supabase leva a pessoa ao Portal.

Parte A — Suas tarefas (na ordem)

A1. GitHub CLI bloqueia a criação da issue e da PR

  • Eu instalo o gh. Num terminal novo, rode gh auth login → GitHub.com → HTTPS → Login with a web browser e confirme o código no navegador.
  • Me avise quando terminar. Não cole tokens no chat.

A2. Vercel — Site (perfin-site)

  • Settings → General → Root Directory = Website
  • Settings → Environment Variables → adicionar NEXT_PUBLIC_PORTAL_URL = https://perfin-portal.vercel.app (Production e Preview)
  • Deployments → último deploy → Redeploy, para o botão “Entrar / Cadastrar” aparecer

A3. Vercel — criar o projeto do Portal

  • Add New → Project → importar caioross/perfin_02, com o nome perfin-portal e Root Directory Aplicativo (Framework: Next.js)
  • Variáveis (Production e Preview):
VariávelValor / origem

Não vão para a Vercel: DATABASE_URL, SUPABASE_DB_PASSWORD, ADMIN_EMAIL, ADMIN_PASSWORD e SUPABASE_POOLER_HOST.

A4. Criar o admin antes de abrir o cadastro

  • Confirme que ADMIN_PASSWORD no .env tem 12 caracteres ou mais e que SUPABASE_POOLER_HOST=aws-0-sa-east-1.pooler.supabase.com está lá
  • Rode python Aplicativo/supabase/scripts/criar_admin.py. Assim ninguém registra o e-mail do admin antes de você. Se a conta já existir, o script só a promove se a senha conferir com ADMIN_PASSWORD.

A5. Supabase → Authentication

  • Sign In / Providers → Email: Enable ✔, Confirm email ✔, Allow new users to sign up ✔ e Minimum password length = 8
  • Sign In / Providers → Google: Enable ✔, com o Client ID e o Client Secret do .env
  • URL Configuration:
    Site URLhttps://perfin-portal.vercel.app
    Redirect URLshttps://perfin-portal.vercel.app/**
    https://*-caioross-projects.vercel.app/**
  • Multi-Factor: TOTP habilitado (usado pelo admin)
SMTP próprio é obrigatório. O envio padrão do Supabase só entrega para os e-mails da equipe do projeto e tem limite de poucos e-mails por hora. Sem SMTP próprio, quem se cadastra não recebe o link de confirmação.
  • Crie uma conta num serviço de envio (ex.: Resend ou Brevo, ambos com plano grátis) e verifique o domínio ou o remetente
  • Supabase → Authentication → Emails → SMTP Settings → Enable Custom SMTP: host, porta 465/587, usuário, senha, remetente “Perfin” (a senha fica só no Supabase)
  • Authentication → Rate Limits: ajuste “emails per hour” (ex.: 30)

O que muda no banco (migration 0010)

  • Cadastro por e-mail passa a nascer como usuario. O acesso só começa depois da confirmação do e-mail.
  • O admin pode bloquear e desbloquear usuários de e-mail, além dos de Google, mas nunca outro admin.
  • Nova tabela limites_uso e função consumir_limite: o limite de perguntas ao assistente (20 a cada 10 minutos, fixo no banco) passa a valer no banco, protegendo o custo do Gemini com o cadastro aberto.
  • RLS continua ligado em todas as tabelas.

Solução de problemas

SintomaCausa provável
redirect_uri_mismatch no GoogleA URI do Supabase não está igual (com https e sem barra no fim) em “URIs de redirecionamento”.
Depois do Google, volta para localhost ou para a página erradaSite URL e Redirect URLs do Supabase não configuradas (A5).
O e-mail de confirmação não chegaSMTP próprio não configurado, limite de e-mails por hora ou caixa de spam.
“Link inválido ou expirado”O template não usa /auth/confirmar?token_hash=…, ou o link já foi usado. Peça outro.
“Acesso não autorizado”Usuário bloqueado pelo admin, ou o admin tentou entrar com Google.
Google recusa a contaA conta não está nos usuários de teste do Google Cloud.
O botão do site não apareceFalta NEXT_PUBLIC_PORTAL_URL no projeto do site, ou falta o redeploy.
